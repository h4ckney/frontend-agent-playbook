# 정족수 상실 비상 복구 검증

[운영 절차](../emergency-quorum-recovery.md) · [CLI 훈련 결과](emergency-quorum-recovery-2026-11-24/recovery-drill.json) · [회귀 테스트](../../analysis/emergency-quorum-recovery.test.mjs)

- 사전 등록한 복구 공개키의 소유를 검증했다. 테스트용 기존 개인키 두 개를 삭제한 뒤, 별도 복구 정족수와 신규 키가 서명한 요청으로 정상 권한을 복구했다.
- 원격 체크포인트를 기록한 직후 실제 CLI 프로세스를 종료했다. 옛 authority의 원격 접근은 차단됐고, 재시작 후 동일한 요청만 로컬로 반영했다. 원격에 기록되기 전 실패 및 동시에 도착한 재개 요청도 검사했다.
- 승인 원문, 정책 revision/digest, 도메인 데이터와 실패한 갱신에서 전진한 TUF 하한을 비교했다. 더 낮은 TUF 버전을 거절했고, 폐기 키 지문은 새 정족수에 재사용할 수 없었다.
- 복구 키 사후 등록, 일반 승인 우회, 권한 증명의 누락, 원격 TUF 하한 변경, 미게시 정상 교체와의 경쟁을 검토했다. 원격에 게시된 후 로컬 재개만 허용하도록 현재 체크포인트와 정확한 직계 후속 항목을 대조한다.
- Node 24.22.3에서 전체 437개(비상 복구 15개 포함), CLI 훈련 4단계, Markdown 102개가 통과했다. 개인키 또는 개인키가 덧붙은 PEM을 공개키로 받지 않으며, 계획이나 witness로 전달하기 전에 거절했다.
- 합성 승인·TUF, 임시 SQLite와 테스트 HTTPS witness를 사용했다. 실제 조직 키, 운영 서비스 복구 시간 및 복구 정족수 보관 실사는 별도다.
