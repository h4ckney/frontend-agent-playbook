# 원격 witness와 호스트 롤백 훈련 근거

[운영·복구 문서](../remote-witness-recovery.md)와 [HTTPS 훈련 기록](remote-witness-2026-11-24/recovery-drill.json). 측정은 임시 로컬 환경에서 HTTPS로 독립 서비스와 통신하는 범위다. 운영 호스트와 백업 서비스 도입은 별도 단계다.

| 관찰 | 근거 |
| --- | --- |
| 응답 누락 및 동일 순번 충돌 차단 | TLS 연결 응답을 중단하거나, 같은 순번에 다른 digest를 가진 유효 서명 응답을 제공해 검증이 멈추는지 확인 |
| 부분 갱신 뒤 하한 유지 | 서명된 TUF 대상 제거 메타데이터를 원격에 커밋한 직후 응답 유실. 서비스 재시작 후 정확한 후속 항목을 적용하고 더 낮은 TUF 버전을 거절 |
| 호스트 롤백과 복구 | 주 DB 및 로컬 witness 파일을 동시에 과거 사본으로 교체. 오래된 상태를 거절하고 이중 승인으로 새 경로에 복구한 뒤 TUF 갱신 요구 |
| 진입점과 회귀 | 일반 refresh/scan CLI, nonce 재사용, 읽기 토큰 분리, 동일 순번 CAS 충돌, 하한 감소, 로컬 DB 유실과 오래된 복구 승인. [실행 테스트](../../analysis/remote-witness.test.mjs) |

리뷰에서는 원격 아래/위 순번과 같은 순번의 충돌을 분리하고, 서명 응답이 오기 전에 성공을 기록하는 경로를 제거했다. 로컬만 확인하는 읽기의 우회를 막기 위해 스캔의 토큰 발급 및 확인에서 원격 상태를 다시 조회한다. 기존 DB와 원격이 크게 어긋날 때는 정확한 한 단계 재개를 적용하지 않고 승인 복구 경로를 사용한다.
