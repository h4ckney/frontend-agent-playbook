# witness 승인 검증과 독립 체크포인트 복구

조직 정책 변경과 복구 경로 변경의 owner·security 승인 서명을 witness에서도 검증한다. 서버는 authority 문서의 digest를 현재 store에 고정한다. 정책 채택은 승인된 변경을 직전 상태에 적용한 결과와 새 체크포인트를 비교한다. 새 경로 복구는 승인된 경로, 직전 체크포인트, 정책, TUF 하한과 승인 이력을 확인한다. 일반 TUF 갱신은 기존 도메인 한 개의 상태와 세대만 바꿀 수 있다. 갱신용 쓰기 토큰은 계속 보호해야 한다. TUF 갱신 결과는 스캐너가 별도로 재검증한다.

신규 원격 등록은 등록할 경로까지 서명한다. v2 이관은 동결된 v2 상태와 서명된 이관 요청을 검증한다. 기존 witness 이력은 유지한다. HTTPS 읽기 형식은 그대로이며, 쓰기 요청의 형식이 바뀌므로 **갱신 작업을 잠시 중지하고 witness 서버와 쓰기 CLI를 같은 배포 창에 교체**한다. 기존 형식으로 작성한 미사용 원격 등록 요청은 업그레이드 후 다시 생성하고 서명한다.

## 호스트 유실 훈련

1. 분석 호스트와 witness 호스트를 서로 다른 복원 단위에 둔다. 담당자는 사전에 등록된 owner·security 키를 각자 보관하고, 분석 호스트 밖에 복구에 필요한 authority, CA 및 접근 자격 정보를 보존한다. 정책 digest, witness 순번, TUF 하한과 승인 이력 건수를 기록한다.
2. 스테이징에서 witness 연결을 끊고 스캔이 종료 코드 2로 실패하는지 확인한다. 연결을 복원한 뒤 분석 호스트의 데이터 볼륨을 유실 상태로 재현한다.
3. [원격 복구 절차](remote-witness-recovery.md#중단과-복구)에 따라 비어 있는 새 경로를 대상으로 두 역할의 승인을 받아 복구한다. 복원 직후 정책 digest, 직전 승인 이력, TUF 하한을 대조한다. 기존 하한보다 낮은 TUF 메타데이터의 거부와 새 검증 완료 후 스캔 성공을 확인한다.
4. 장애 시각, 승인 완료 시각, 첫 정상 스캔 시각을 기록한다. 실제 복구 소유권과 시간 목표는 스테이징 담당자가 확인한다.

## witness 호스트 롤백 대비

witness 서비스 설정에 `"checkpointDirectory": "/independent-volume/org-checkpoint"`를 추가한다. 이 저장소와 서비스 설정은 witness 이력 DB와 별도의 백업·복원 정책으로 관리한다. 새로 설치할 때는 기존 `--initialize`로 두 DB를 만든다. 별도 볼륨은 SQLite가 요구하는 잠금과 동기화가 보장되어야 한다. 여러 호스트에서 SQLite 파일을 직접 여는 네트워크 파일 공유는 피한다. [SQLite 네트워크 파일시스템 문서](https://www.sqlite.org/useovernet.html)

기존 witness에는 쓰기를 멈춘 상태에서 승인된 외부 운영 기록의 최신 digest를 확인한다. 서비스에 `checkpointDirectory`를 설정하고 아래 명령으로 최초 결합한다. 입력 digest가 틀리거나 기존 독립 체크포인트와 현재 이력이 다르면 시작이 차단된다. 이후 재시작에서는 플래그를 생략한다. 이력과 체크포인트 DB에 조직 정보가 모두 들어 있으므로 두 볼륨에 접근 통제와 백업을 적용한다.

```sh
node verification/remote-witness-server.mjs SERVICE.json --bind-checkpoint sha256:EXPECTED_DIGEST
```

새 상태를 독립 체크포인트에 먼저 커밋한 뒤 witness 이력 DB의 커밋을 완료한다. 시작할 때와 새 요청에 응답하기 전에 순번과 digest를 비교한다. 체크포인트 누락, 같은 순번의 충돌, witness 이력의 과거 복원은 서비스가 차단한다.

| 관측 상태 | 복구 |
| --- | --- |
| 독립 체크포인트만 정확히 한 단계 앞서며 직전 digest가 일치 | 서비스 중지 상태에서 `node verification/remote-witness-server.mjs SERVICE.json --repair-checkpoint`로 이미 검증된 한 항목을 복사한다. 분석 호스트도 한 단계 뒤처졌다면 `reconcile`을 실행한다. |
| 같은 순번의 충돌, 여러 단계의 이력 유실, 혹은 이력 DB의 완전 유실 | 서비스를 중지하고 독립 체크포인트와 동일한 witness 이력 백업을 복원한다. 필요하면 그 백업에서 바로 다음 한 항목만 위 방식으로 복구할 수 있다. 최신 상태를 입증할 백업 없이 운영을 재개하면 안 된다. |
| 독립 체크포인트 볼륨의 유실 | 백업 운영자가 별도로 보존한 최신 체크포인트를 복원한다. 최신 체크포인트를 확인할 때까지 쓰기와 검증을 중단한다. |

이 보장은 독립 체크포인트와 서비스 설정이 최신인 경우에 적용된다. 두 볼륨과 설정을 함께 과거로 되돌릴 수 있는 주체는 별도 운영 신뢰 경계에 있다. 코드 롤백 절차에도 독립 체크포인트 확인을 포함한다. 체크포인트 파일을 새로 초기화하거나 보호 기능이 없는 서버 버전으로 복원하지 않는다.

## 검증 근거

`node scripts/drill-witness-recovery.mjs --output NEW_RECEIPT.json`으로 호스트 유실과 witness 롤백을 순서대로 재현한다. 별도 HTTPS 프로세스와 임시 저장소로 실행되며, 실제 스테이징의 두 호스트와 별도 볼륨, 실제 키 담당자, 전원 장애는 스테이징 수락 훈련에서 검증한다. 테스트 소요 시간은 로컬에서 자동으로 발급한 승인 시간을 포함하며 운영 복구 목표로 사용하지 않는다.
