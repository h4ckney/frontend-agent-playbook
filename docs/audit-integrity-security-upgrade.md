# 분석 신뢰도와 보안 실행 문맥 개선

기준: `e9be632b37e5a9cb80d1ce5cae1843b5a820b540` · 검토일: 2026-10-30. 이 문서는 1차 triage 구현 이후 확인한 반례와 이번 수정 범위를 정리한다. [기존 계획](audit-upgrade-plan.md)의 66개 테스트·14개 브라우저 확인은 당시 기록이며 이번 변경의 검증으로 재사용하지 않는다.

## 이번 변경과 이유

| 확인한 문제 | 변경 | 검증 근거 |
| --- | --- | --- |
| 일반 문자열의 `do not edit`가 파일 전체를 숨기고 기존 위험을 해결로 처리 | 시작 위치의 명시적 생성 주석만 제외. 새 헤더 제외는 부분 분석·미검증으로 유지 | analyzer/CLI의 일반 문자열·주석, 헤더 전환, exit 3 회귀 검사 |
| 같은 탐지기라는 이유로 별개의 새 위험을 파일 이동으로 처리하여 CI 통과 | 실제 이동 근거가 없으면 새 항목 유지. 과거 항목의 소멸만 미검증 | 별개 인증정보 저장 경로의 exit 1; 탐지기 버전 변경의 소멸도 미검증 |
| 탭·가져오기·저장 거부 후 재연결이 검토 기록을 덮어씀 | 변경마다 독립 저장, 합치기, 같은 프로젝트의 메모리 상태 보존 | 두 탭의 오래된 상태, 빈 백업, 저장 오류, 미래 시각의 백업에서 다시 열기 |
| 137자의 긴 프로젝트 ID가 390px 화면을 넘침 | 동적 상태 문구를 줄바꿈하고 근거 펼침·초점을 유지 | 회귀 시나리오와 실제 브라우저 확인을 구분하여 근거 기록 |
| 실제 검증 함수가 공개 JSON Schema보다 느슨함 | 결과·baseline 구조를 공개 스키마로 검사. 브라우저 복사본 생성·동기화 검사 | 도달 가능한 필수 필드 삭제, 중첩 enum/type/추가 필드/날짜 음성 검사 |
| 다른 서버를 검사하고 현재 체크아웃 해시를 증거로 남길 수 있음 | 실제 제공 HTML·JS·CSS를 실행 전후 비교, 브라우저가 받은 응답도 비교 | 오래된 서버·중간 변경 거부 HTTP 검사; 전체 브라우저 실행은 별도 |
| CI가 지원 종료된 Node 20 사용 | 지원 계열 22/24/26 최신 패치 CI, 로컬 권장 계열 24 | 원격 CI 결과와 실제 로컬 Node 버전을 별도 기록 |

검토 상태는 새 내보내기에서 schema v2를 사용한다. v1 백업·기존 저장은 읽어 합친다. 동일 발견의 충돌은 논리적 검토 차수, 검토 시각, 같은 시각이면 열려 있는 상태 우선으로 정한다. 명시적인 동작은 저장된 상태를 먼저 읽고 차수를 올리므로 미래 시각의 백업이 다시 열기를 막지 않는다. 새 저장은 독립 journal이므로 서로 다른 탭이 같은 저장 키를 덮어쓰지 않는다. 자동 삭제·압축은 하지 않으며 브라우저 용량에 도달하면 메모리 상태와 내보내기를 유지한다.

닫기는 계속해서 검토 결정이다. canonical 발견, baseline, CI 예외, GitHub 이슈 종료와 구분한다. 새로운 범위·탐지기·영향·근거는 재검토한다.

## 보안 결과를 해석하는 방법

선택 파일 → 의존성·런타임 근거 수집 → 유한한 오프라인 권고 비교 → canonical 결과·스키마 검증 → baseline/CI → 로컬 검토 화면 순서다. [보안 문맥](security-context.md)에 버전과 조건, [전체 모듈 권고 조회](dependency-advisories.md)에 별도 온라인 조회를 설명한다.

- 기본 분석은 파일을 외부로 보내지 않는다. npm lock v2/v3·Composer lock, 선언 파일, Node/PHP pin, Docker 기본 최종 stage·빌드 stage와 일부 CI 설정을 읽는다.
- 버전 범위, lock의 정확한 버전, 설정된 실행 버전, 실제 설치·배포 버전은 구분한다. 런타임·빌드·개발·미확인을 근거와 함께 보존한다.
- Node Brotli, PHP 요청 처리, React RSC와 Next 이미지 처리는 버전 일치와 실행 조건을 함께 보여준다. 일반 React 클라이언트나 PHP 파일의 존재만으로 취약하다고 판정하지 않는다.
- 같은 권고의 별칭·상위와 하위 패키지 관계는 한 부모로 모으고 각 모듈 위치를 자식으로 남긴다. 다른 원인의 취약점은 별도다.
- `scripts/query-osv.mjs`는 명시적으로 실행할 때 잠긴 npm·Packagist 패키지 이름·버전만 OSV로 보낸다. 프로젝트 코드·경로·단계는 로컬에 둔다. 사설 패키지 이름도 정보를 드러낼 수 있다.
- 외부 권고 보고서는 별도 검토 자료다. 원본 결과나 CI·검토 상태를 자동 수정하지 않는다. 실패·미지원·제한 도달은 안전 판정으로 바꾸지 않는다.

## 현재 아키텍처와 운영 경계

| 구성 | 책임 | 별도 확인 사항 |
| --- | --- | --- |
| `analysis/analyzer.js` | 예산·제외 정책과 좁은 소스/CSS 패턴 | AST·DOM·cascade·전체 데이터 흐름 분석 아님 |
| `analysis/security-context.js` | 버전 목록, 사용 단계, 권고 스냅샷 | 실제 설치·서버·OS·SAPI·vendor backport 미확인 |
| `analysis/audit-contract.js`, `schemas/` | 결과 정규화·검증·baseline·판정 | 탐지기 변경과 부분 범위는 해결로 단정하지 않음 |
| `analysis/app.js`, `triage-state.js` | 표시·검토 기록·합치기 | 로컬 저장이며 외부 이슈와 자동 동기화하지 않음 |
| `scripts/query-osv.mjs` | 명시적 온라인 패키지 권고 조회 | 전체 보안 스캔·악성 패키지·OS 취약점 검사 아님 |
| `scripts/verify-dashboard.mjs` | 로컬 대시보드 상호작용과 소스 출처 확인 | 실제 제품의 모든 URL·기기·상태를 보증하지 않음 |
| `.github/workflows/validate.yml` | PR/main의 문서·계약·단위 검사 | 실제 브라우저 E2E와 서비스 배포는 별도 |

저장소 자체는 배포 서비스를 포함하지 않는 가이드·정적 대시보드·Node CLI다. PHP 서버나 실제 제품 의존성을 설치하지 않았다. 근거의 PHP·Node·RSC 취약 버전은 **합성 입력**이다. 테스트가 이런 버전을 출력하는 것은 이 저장소가 해당 취약 패키지를 실행한다는 뜻이 아니다.

## 검증과 전달

[이번 근거 기록](evidence/audit-integrity-security-2026-10-30.md)에서 로컬 테스트, 실제 브라우저, 원격 CI, 커밋/머지를 각각 확인한다. 로컬 검사 환경이 지원 종료된 Node 25라면 이를 Node 24 실행으로 표현하지 않는다. 권장 개발 환경은 `.node-version`의 24 계열 최신 보안 패치이며 CI는 22/24/26을 확인한다.

반영 경로는 작업 브랜치 → PR → 독립 반례 검토·CI → 사용자 승인 범위의 머지다. 롤백은 해당 PR의 변경을 되돌린다. 기존 v1 검토 원본 저장은 지우지 않지만, 오래된 UI는 v2 백업을 읽지 못하므로 필요하면 새 UI에서 내보낸 상태를 함께 보관한다. 대상 서비스 배포·의존성 업그레이드·외부 이슈 게시를 수행한 것으로 표현하지 않는다.

문제가 생기면 우선 해당 발견의 `observedFact`와 `securityContext.coverage.gaps`, 다음으로 `snapshot.checkedAt`과 원본 권고, 마지막으로 실제 설치·배포 버전과 실행 경로를 확인한다. 기록 문제는 검토 JSON을 먼저 내보내고 같은 프로젝트 ID·원본 v1 저장·journal을 확인한다.

후속 검사는 계획이며 예약·운영 중인 자동화가 아니다. 정적 CSS 후보만으로 화면 결함을 확정하지 않는다.
