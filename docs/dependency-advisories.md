# 모듈별 최신 권고 조회

기본 분석은 네트워크 없이 실행됩니다. [보안 실행 문맥](security-context.md)의 유한한 권고 스냅샷과 별도로, 설치할 버전을 잠근 npm/Composer 모듈을 현재 OSV 데이터와 비교할 수 있습니다. 브라우저에서 폴더를 선택하거나 기본 CLI 분석을 실행하는 것만으로 외부 조회가 발생하지 않습니다.

## 실행

먼저 오프라인 분석 JSON을 만듭니다. `--output`은 분석 대상 루트 안의 경로입니다. 기존 보고서를 보존할 수 있도록 조회 결과는 매번 새 폴더에 저장합니다.

```sh
node bin/frontend-agent-audit.mjs scan --root /path/to/project --format json --output audit.json
node scripts/query-osv.mjs --scan /path/to/project/audit.json --output /path/to/review-20261030
```

두 번째 명령이 외부 조회를 명시적으로 실행합니다. CLI는 먼저 입력이 유효한 AuditResult 계약인지 확인하며, 유효하지 않으면 조회하지 않습니다. OSV에 **생태계·패키지 이름·잠긴 정확한 버전**을 전송합니다. 추가 페이지 토큰과 권고 ID도 OSV에 보냅니다. 소스 코드, 프로젝트 이름, 로컬 경로, 실행 단계 정보는 보내지 않습니다. 사설 패키지의 이름도 조직 내부 정보를 드러낼 수 있으므로 외부 전송이 허용된 입력으로 실행합니다. 프록시 등 실행 환경의 일반적인 HTTP 동작은 별도로 적용됩니다.

이 도구는 프로젝트 스크립트, `npm`, `composer`, 설치 명령, 서비스 기동 명령을 실행하지 않습니다. 외부 서버 응답에 들어 있는 URL을 따라가지 않으며, 고정된 `api.osv.dev` API만 호출합니다.

출력은 아래 두 파일입니다.

- `dependency-advisories.json`: 입력 분석의 SHA-256, 조회 시각, 조회한 모듈과 버전, 원래 경로·선언 단계, 권고 상세·별칭, 실패·누락 내역.
- `dependency-advisories.md`: 권고를 부모 항목 하나로 묶고 관련 모듈·버전·경로·단계를 하위에 표시하는 검토 문서.

`--help`는 네트워크 없이 사용법을 표시합니다. 기존 결과 파일을 덮어쓰지 않습니다. 종료 코드 `0`은 제출한 범위의 조회가 완료되었다는 뜻이며 취약점이 없다는 뜻이 아닙니다. 부분 조회·조회 대상 없음·입출력 오류는 `2`입니다. 권고 발견 수에 따른 CI 차단 정책은 제공하지 않습니다.

## 버전과 실행 단계

| 입력 | 처리 | 남는 한계 |
| --- | --- | --- |
| npm lock v2/v3의 `locked-exact` | `npm` 생태계의 같은 이름·버전으로 조회 | 설치·배포·호출 경로는 미검증 |
| Composer lock의 `locked-exact` | OSV `Packagist`로 변환, 선행 `v` 제거 후 조회 | 실제 PHP 버전과 SAPI는 별도 확인 |
| manifest의 정확한 버전·범위·workspace 참조 | 같은 디렉터리·생태계·이름의 lock 항목이 있으면 선언 근거로 따로 보존하고, 없으면 누락 사유 표시 | 선언은 설치된 버전의 증거가 아니며 버전 범위 호환성을 계산하지 않음 |
| Node/PHP 버전 | 이 조회에서 제외 | 언어 런타임을 동명의 npm 모듈로 조회하면 잘못된 결과가 됨 |
| 지원하지 않는 lock 형식·부분 스캔 | 입력의 누락을 유지 | 별도 설치 목록·SBOM 등 필요 |

같은 디렉터리의 lock 근거가 있는 manifest 선언은 `covered-by-lock`으로 별도 보존하며 중복된 누락으로 집계하지 않습니다. 선언 버전과 잠긴 버전이 서로 호환된다는 뜻은 아닙니다. 다른 디렉터리 또는 lock에 없는 이름의 선언은 계속 미확인 범위로 남습니다.

같은 생태계·이름·버전은 한 번만 조회하고 각 모듈의 원래 경로와 `runtime`, `build`, `development`, `unknown`은 모두 보존합니다. OSV가 같은 취약점을 뜻한다고 명시한 별칭은 하나의 부모 항목으로 모으고 원본 레코드를 함께 남깁니다. CVE/GHSA ID가 다르다는 이유만으로 같은 문제를 중복 집계하지 않습니다. 같은 이름의 다른 버전은 독립적으로 조회합니다.

개발·빌드 의존성도 CI 자격증명, 개발 PC, 빌드 산출물에 영향을 줄 수 있습니다. 런타임 설치 그룹에 있는 모듈도 배포 파일에 포함되지 않거나 취약한 기능을 호출하지 않을 수 있습니다. 따라서 단계는 노출 판단의 근거이며 자동으로 위험을 삭제하거나 확정하는 조건이 아닙니다.

## 조회 범위와 실패

현재 한 번의 실행은 최대 200개 고유 패키지, 패키지당 최대 3페이지·1,000개 권고 ID, 최대 200개 권고 상세를 조회합니다. 한 요청은 15초, 응답은 4MB로 제한합니다. 제한 도달, HTTP 실패, 응답 식별자·패키지 불일치, 해석 실패가 있으면 해당 모듈을 `incomplete`로 남깁니다. 실패한 조회를 `none-reported`로 바꾸지 않습니다. 이름·버전이 맞는 상세 레코드를 받더라도 실제 악용 경로가 확인된 것은 아닙니다.

`none-reported`는 그 조회가 완결되었고 OSV가 해당 버전에 대해 반환한 레코드가 없었다는 뜻입니다. 알려지지 않은 취약점, 미수집 데이터, 런타임·OS·컨테이너 위험까지 없다는 뜻이 아닙니다. 지원하지 않는 입력이나 읽기 누락이 있으면 전체 결과는 `partial`로 표시합니다. 기본 분석의 권고 스냅샷이 최신 전체 데이터베이스로 바뀌는 것도 아닙니다.

철회된 권고는 이력을 보존하고 `withdrawn`으로 표시합니다. CVSS 벡터·패치 범위·수정 버전은 원본 OSV 상세에 남기며, 이 스크립트가 임의의 위험 점수나 안전한 업그레이드 버전을 계산하지 않습니다. 수정 전에는 공급자 권고, 배포 버전, 사용 기능, 호환성과 회귀 검증을 확인합니다.

이 보고서는 별도의 검토 자료입니다. 원본 AuditResult, 기준선, 로컬 닫기 상태, CI 예외, GitHub 이슈 상태를 변경하지 않습니다. 필요하면 보고서의 부모 권고와 모듈별 근거를 보고 실제 조치 항목을 작성합니다.

## 검증과 근거

다음 검증은 외부 네트워크 없이 API 응답 fixture로 실행됩니다.

```sh
node --test scripts/query-osv.test.mjs
```

중복 좌표 조회 방지, 단계·경로 보존, 페이지별 쿼리 대응, 별칭 중복 제거, 실패·제한·잘못된 식별자, 철회 이력과 보고서 텍스트 처리를 검증합니다. 이 테스트 통과가 실제 서비스의 최신 취약점 조회 완료를 뜻하지 않습니다.

2026-10-30에 확인한 1차 자료:

- [OSV batch 조회](https://google.github.io/osv.dev/post-v1-querybatch/): 결과는 쿼리 순서와 대응하며, ID만 반환하므로 상세 조회가 필요합니다. 페이지 토큰도 쿼리별로 처리합니다.
- [OSV 단일 조회](https://google.github.io/osv.dev/post-v1-query/): 생태계·이름·버전 식별 규칙과 페이지 처리.
- [OSV 권고 상세](https://google.github.io/osv.dev/get-v1-vulns/): 권고 ID별 상세 레코드.
- [OSV 스키마](https://ossf.github.io/osv-schema/): 패키지 식별, 별칭, 영향 범위, 철회·수정 시각의 의미.
