# Keyless evidence — controlled offline trust domain

This example contains actual cryptographic signatures under **controlled test CA/CT/Rekor keys**, generated by the [fixture generator](../../analysis/fixtures/keyless-evidence.mjs). No private keys, OIDC bearer tokens, production Fulcio certificates or live Rekor entries are stored. The certificate's issuer/SAN are test claims, not proof of a real GitHub Actions login.

Use a supported Node runtime (`^22.22.2 || ^24.15.0 || >=26.0.0`). Install the tool verifier once, with lifecycle scripts disabled:

```sh
npm ci --prefix verification/sigstore --omit=dev --ignore-scripts --no-audit --no-fund
node verification/sigstore-root-digest.mjs examples/keyless-evidence/trusted-root.json
node bin/frontend-agent-audit.mjs scan --root examples/keyless-evidence --trust-policy public-policy.json --sigstore-trusted-root trusted-root.json --format json
```

The policy pins the canonical JSON root hash plus literal OIDC issuer and certificate identity. Both files must be selected explicitly. Omitting either leaves the reports unverified; a root included by the bundle cannot authenticate itself. This sample policy/root is only for this example and must not become an organization's production trust.

The root's formatting may change without changing its canonical digest. Changing any root value requires independent review and a new policy pin. Observations were generated on 2026-11-22; the 30-day report freshness limit and policy validity still apply. Historical signed time can validate a short-lived leaf after its expiry; it does not extend report freshness or policy lifetime.

In the dashboard, select this folder and then `public-policy.json` separately. It shows `sigstore-node-verifier-required` and keeps authentication **unverified**: the official verifier is Node-only. Browser success JSON is never imported as trusted verification. See [supported profile, assumptions and recovery](../../docs/sigstore-keyless.md).
